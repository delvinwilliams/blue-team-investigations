## 📧 1. Phishing Email Investigation

### Objective
Analyze suspicious emails to identify phishing indicators and determine whether a message presents a potential security threat.

### Skills Practiced
- Reviewing email headers and sender information.
- Identifying suspicious links and domains.
- Examining email attachments.
- Recognizing common phishing techniques.
- Documenting suspicious indicators.

### Investigation Process
1. Review the reported email and its contents.
2. Examine sender information and available metadata.
3. Identify suspicious URLs and attachments.
4. Analyze available artifacts using appropriate tools.
5. Document findings and recommended response actions.

### What I Learned
Phishing investigations require more than identifying a suspicious-looking message. Reviewing email metadata, links, attachments, and other indicators can help determine whether further investigation is necessary.

## 📊 2. SIEM Investigation Using Splunk

### Objective
Use Splunk to investigate security events, review log data, and identify potentially suspicious activity.

### Skills Practiced
- Searching and filtering security logs.
- Investigating authentication events.
- Reviewing event timestamps.
- Correlating related security events.
- Documenting investigation findings.

### Investigation Process
1. Identify the security activity requiring investigation.
2. Search relevant log sources in Splunk.
3. Filter events by timestamps and other available fields.
4. Examine related events for suspicious patterns.
5. Record findings and determine whether further investigation is needed.

### What I Learned
Splunk makes it possible to investigate large collections of logs and identify activity that may not be obvious when reviewing individual events.

Understanding how to filter and correlate events is an important skill for SOC analysts.

## 💻 3. Windows Digital Forensics

### Objective
Investigate Windows system artifacts to reconstruct user activity and identify evidence relevant to a security investigation.

### Tools and Artifacts
- Windows Event Logs
- Prefetch Files
- Jump Lists
- Browser History
- Recycle Bin Artifacts
- Autopsy

### Investigation Process
1. Identify the available forensic evidence.
2. Examine Windows artifacts for signs of application execution.
3. Review available browser and file activity.
4. Compare timestamps to establish a sequence of events.
5. Document relevant findings.

### What I Learned
Windows systems contain artifacts that can help investigators understand what happened during a security incident.

Artifacts such as Prefetch files, Jump Lists, and browser history can provide useful context when reconstructing activity.

---

## 🧠 4. Memory Forensics With Volatility

### Objective
Examine captured system memory to identify processes, network activity, and other artifacts that may assist an investigation.

### Tools Used
- Volatility 2
- Volatility 3
- Windows Memory Dumps

### Skills Practiced
- Enumerating running processes.
- Reviewing parent-child process relationships.
- Identifying unusual process activity.
- Examining available network connection artifacts.
- Investigating process-related evidence.

### Investigation Process
1. Identify the available memory image.
2. Determine appropriate analysis methods.
3. Enumerate processes and inspect their relationships.
4. Review relevant memory artifacts.
5. Document observations and findings.

### What I Learned
Memory analysis can reveal valuable evidence about processes and activity present when a memory image was captured.

Examining process relationships and other memory artifacts can help investigators identify behavior that requires closer examination.

## 🌐 5. Threat Intelligence Investigation

### Objective
Use threat intelligence platforms to research known threats, investigate indicators of compromise, and better understand attacker behavior.

### Tools and Concepts
- MISP
- Indicators of Compromise (IOCs)
- Threat Intelligence Reports
- YARA Rules
- Threat Actor Research

### Skills Practiced
- Searching threat intelligence databases.
- Reviewing indicators associated with known threats.
- Researching malicious domains and other artifacts.
- Interpreting threat intelligence reports.
- Connecting intelligence findings to defensive investigations.

### What I Learned
Threat intelligence provides additional context during security investigations.

Understanding how to research indicators and interpret intelligence reports can help analysts make more informed decisions about suspicious activity.
